## Key Implementation Decisions

- **Highlight extraction:** LLM-powered (more accurate, uses existing OpenAI integration)
- **Daily scheduling:** Vercel Cron (native, free tier supports 1/day)
- **Audience voting:** Requires login (anti-spam, ties votes to users)
- **Circuit breaker:** Add to SecondMe API calls + SSE total timeout (for unattended Cron runs)

## Accepted Scope (added to this plan)

### 1. Date Highlights / "Best Quotes"
After dates complete, use LLM to extract the most interesting/romantic/funny conversation snippets. Display on scoreboard. Users share because "look what my Agent said."

**Implementation notes:**
- Extract after `runDate` completes, store as new model or JSON field on DateSession
- Minimum 4 messages required for extraction
- Fallback: if LLM fails, skip highlights (show "no highlights")
- Display on scoreboard page with quote cards

### 2. Social Share Cards
Generate shareable "score card" images (OG image) per agent: avatar emoji, name, total score, best match, highlight quote. One-click share to WeChat/Weibo/Twitter.

**Implementation notes:**
- Extend existing `opengraph-image.tsx` pattern
- New API route: `/api/agents/[id]/share-card` returning PNG
- Use Next.js ImageResponse API
- Cache generated images

### 3. Audience Voting System
On Watch page, logged-in observers can vote on active dates: "chemistry!" or "not feeling it." Like reality TV audience interaction.

**Implementation notes:**
- New Prisma model: `Vote` (userId, dateSessionId, voteType, createdAt)
- New API route: `/api/dates/[id]/vote`
- Auth required + rate limit (1 vote per user per date)
- Display vote counts on Watch page
- Results shown on scoreboard

### 4. Agent Chemistry Prediction
Before matches happen, display AI-predicted "chemistry index" using existing matchmaker scores. Fire/iceberg emoji to represent prediction. Builds anticipation.

**Implementation notes:**
- Reuse `computeSmartCompatibility` from matchmaker.ts
- Display on lobby/dates page before event starts
- Visual: emoji scale (❄️ → 🔥) based on score ranges

### 5. Daily Auto Events (Vercel Cron)
Scheduled task creates and runs a dating event daily. Users just create agents; system handles matchmaking and dates automatically. Results ready next day.

**Implementation notes:**
- New API route: `/api/cron/daily-event` with CRON_SECRET verification
- `vercel.json` cron config (e.g., daily at 20:00 UTC+8)
- Idempotency: check if today's event already exists
- `ENABLE_DAILY_EVENT` env var as kill switch
- Detailed execution logging
- Handle: 0 agents, odd agents, previous event not finished

## Architecture Changes (updated by /plan-eng-review)

### Enhanced withRetry (replaces circuit breaker)
- Add 429 detection with exponential backoff to `withRetry` in `date-engine.ts`
- Add total timeout parameter for SSE streams (5 minutes per date session)
- Circuit breaker pattern dropped: serverless instances don't share memory state

### Cron Architecture (simplified)
- Cron only creates Event + matchmaking pairings (completes in <10s)
- Dates run via client-side trigger or separate per-minute Cron
- Avoids Vercel Hobby 10s timeout limit

### Share Card Route (corrected)
- Route: `/api/events/[eventId]/share/[agentId]` (event-scoped, not agent-scoped)
- Stats are per-event, so card must be event-scoped for correct semantics and caching

### Chemistry Prediction (corrected)
- Display: Lobby heatmap showing all-pairs compatibility matrix
- Does NOT reveal actual pairings before event starts
- Requires exporting `computeSmartCompatibility` from matchmaker.ts

### Public Access (prerequisite for sharing)
- Remove `/scoreboard` and `/watch` from PROTECTED_ROUTES in middleware.ts
- Allow unauthenticated read-only access to event results

### New Data Models (Prisma)
```prisma
model Vote {
  id            String   @id @default(cuid())
  userId        String
  dateSessionId String
  voteType      String   // "chemistry" | "not_feeling_it"
  createdAt     DateTime @default(now())

  user        User        @relation(fields: [userId], references: [id], onDelete: Cascade)
  dateSession DateSession @relation(fields: [dateSessionId], references: [id], onDelete: Cascade)

  @@unique([userId, dateSessionId])
  @@index([dateSessionId])
}
```

DateSession gains: `highlights String?` (JSON field for LLM-extracted quotes)

### Highlights Extraction
- Async fire-and-forget after date completes
- Stored as JSON field on DateSession
- Minimum 4 messages required
- LLM failure gracefully returns null
